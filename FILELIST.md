# FILELIST.md

- `.gitignore` — Git ignore rules.
- `.gitattributes` — Marks binary assets (`.syso`, `.ico`, `.icns`, `.png`, `.zip`) so Git never applies line-ending conversion that would corrupt them.
- `go.mod` — Go module definition file.
- `.github/workflows/release.yml` — GitHub Actions: on a `v*` tag, builds the universal macOS `.app` (version injected) and the Windows `setup.exe` installer, publishes them to a GitHub Release, and bumps the multi-claude-switcher cask in `miou1107/homebrew-tap` to the new version + macOS zip SHA256 (needs the `HOMEBREW_TAP_TOKEN` secret).
- `go.sum` — Go module checksum file.
- `README.md` — User-facing overview: what it does, install, usage, troubleshooting (English). Reference and contributor material lives in `docs/`.
- `README.zh-TW.md` — Traditional Chinese counterpart of the README (mirrors its structure).
- `FILELIST.md` — Inventory of project files and purpose.
- `CHANGELOG.md` — Project version and change history.
- `LICENSE` — MIT license text.
- `bin/mcs` — Compiled CLI binary executable.
- `bin/mcs-tray` — Compiled System Tray GUI binary executable.
- `cmd/mcs/main.go` — Go CLI entry point (`mcs status`, `sync`, `switch`, `backup`, `restore`).
- `cmd/mcs-tray/main.go` — Go System Tray GUI entry point (cross-platform menu-bar / tray quick switcher).
- `cmd/mcs-tray/trayicon_darwin.go` — macOS tray icon (template PNG via SetTemplateIcon).
- `platform/protocolhandler_windows.go` — Points the `claude://` URL handler (`HKCU\Software\Classes\claude\shell\open\command`) at the active profile while the switcher runs, so a sign-in callback opens the profile the user switched to rather than the default one, and restores Claude Desktop's own registration on exit. Re-reads the exe path on every write and rewrites the pristine form to restore, so a Claude update cannot leave a stale path behind.
- `platform/protocolhandler_windows_test.go` — Tests for the parsing and rendering behind that rewrite: exe extraction from quoted/unquoted forms, both rendered command shapes, reading a profile back out, and a round trip proving repeated rewrites neither accumulate arguments nor lose the exe.
- `cmd/mcs-tray/trayicon_windows.go` — Windows tray icon (icon.ico via SetIcon).
- `cmd/mcs-tray/trayicon_other.go` — Tray-icon no-op for unsupported OSes.
- `cmd/mcs-tray/assets/icon.png` — Menu bar template icon (eyes glyph; recolored by macOS for light/dark).
- `cmd/mcs-tray/assets/appicon-1024.png` — Color 1024px app icon source (eyes), converted to icon.icns at packaging time.
- `cmd/mcs-tray/assets/icon.ico` — Color multi-resolution Windows icon (16–256px) for the tray/exe.
- `cmd/mcs-tray/rsrc_windows_amd64.syso` — Windows resource object (generated from `icon.ico` via `rsrc`) that compiles the app icon into `mcs-tray.exe`; auto-linked for windows/amd64 so the Start Menu / taskbar / Explorer show the icon.
- `scripts/gen-icons/main.go` — Standalone generator (`go run`) that rasterizes the eyes mark from geometry into all icon assets (app PNG, menu-bar template, Windows .ico, doc PNG); no external tools needed.
- `scripts/gen-screenshot/main.go` — Standalone generator (`go run`) that renders the account panel with placeholder accounts, so the README screenshot comes from the shipped UI code instead of a photograph that can go stale or leak real account names.
- `docs/assets/icon.png` — 512px color icon for README and documentation.
- `docs/assets/panel.png` — README screenshot of the account panel, rendered from the shipped UI with placeholder accounts (regenerate with `scripts/gen-screenshot`).

- `cmd/mcs-tray/panel_windows.go` — Windows-only WebView2 popup panel host (`mcs-tray.exe --panel`, long-lived: parks off-screen and shows on the tray's `SHOW x,y`, or shows immediately with `--anchor X,Y` when launched by hand): borderless topmost window, JS bridge via jchv/go-webview2 Bind, parks off-screen again on outside-click (WM_ACTIVATE WA_INACTIVE) rather than exiting, re-rendering the account list while parked so the next show is instant. Places itself next to the clicked tray icon using the anchor point and the work area of that monitor (MonitorFromRect + GetMonitorInfoW), so it follows the taskbar to any edge and onto secondary displays. Parks the window off-screen (never hidden — WebView2 stops rendering while hidden and does not resume) while go-webview2 embeds the browser, since it creates the window already visible at the default position, and moves it into view only once styled, sized and loaded. Applies `WS_EX_TOOLWINDOW` as soon as the window exists so no taskbar button ever appears for it, takes the foreground via an AttachThreadInput handover, arms the outside-click dismissal only after confirming the window reached the foreground, and logs window position/visibility/focus so a panel that starts but never appears is diagnosable. MessageBox+install-link fallback when the WebView2 Runtime is missing.
- `cmd/mcs-tray/panel_other.go` — Non-Windows stub for the panel entry point (never called on darwin — macOS uses `cmd/mcs-menubar`).
- `cmd/mcs-tray/onready_windows.go` — Windows-only tray `onReady`: starts and supervises one long-lived panel process (respawning it with backoff if it dies, killing it on tray exit); left-click (`systray.SetOnTapped`) toggles the panel by sending it `SHOW x,y` on stdin with the cursor position, having first granted it the foreground right; right-click keeps a single **Quit** item as the escape hatch for when the WebView2 panel cannot open. Reads the panel's stdout for `MCS_SHOWN`/`MCS_HIDDEN` (which drive the toggle) and `MCS_QUIT` (which shuts the tray down too).
